# プロダクト要求定義書 — 図書館蔵書チェッカー

| 項目 | 内容 |
|------|------|
| プロダクト名 | 図書館蔵書チェッカー |
| バージョン | 1.0.0 |
| 作成日 | 2026-04-06 |
| 対象プラットフォーム | Chrome 拡張機能（Manifest V3） |

---

## 1. 背景と目的

### 1.1 背景

書籍を購入する前に図書館で借りられるかどうか確認したいというニーズがある。しかし従来は、書籍ページを見ながら別タブで図書館のWebサイトやカーリル（https://calil.jp）を開き、ISBNを手動で入力して検索する必要があった。この作業は煩雑であり、特に購入検討中に複数の書籍をチェックするユーザーにとって大きな障壁となっていた。

### 1.2 目的

Amazon.co.jp・楽天ブックスの書籍ページを閲覧している最中に、その書籍が近くの図書館で借りられるかどうかをページを離れることなくリアルタイムで確認できるようにする。

---

## 2. ターゲットユーザー

| ユーザー層 | 説明 |
|-----------|------|
| 図書館利用者 | 書籍を購入する前に図書館での貸出状況を確認したいユーザー |
| 節約志向のユーザー | まず図書館で読んでから購入するか判断したいユーザー |
| 読書家 | 多数の書籍を検討するため、毎回手動検索する手間を省きたいユーザー |

**前提条件:** ユーザーはカーリルAPIキー（無料取得可）を持っているか、取得できる。

---

## 3. ユーザーの課題

| 課題 | 現状の問題 |
|------|----------|
| 蔵書確認の手間 | Amazon等で気になった本を図書館で検索するには、タブを切り替えてISBNを手動コピーする必要がある |
| 複数図書館の横断確認 | 自宅・勤務先・よく行く図書館など複数館を一度に確認できる手段がない |
| 貸出状況のリアルタイム性 | 図書館サイトで確認しても現在の貸出状況がわかりにくい場合がある |
| 予約への誘導 | 貸出中でも予約できる場合があるが、予約ページへのアクセスが面倒 |

---

## 4. プロダクト目標

### 4.1 主要ゴール

1. **ゼロ操作での蔵書確認**: 書籍ページを開いた時点で自動的に蔵書状況を表示する
2. **複数図書館の一括確認**: 最大5館の蔵書状況を1画面で確認できる
3. **予約へのスムーズな導線**: 貸出状況に応じて図書館の予約ページへ直接遷移できる

### 4.2 成功指標（参考）

- 対応ページを開いた際に蔵書確認ウィジェットが正常に表示される
- カーリルAPIのポーリング完了後、3秒以内に結果が表示される（通常時）
- Amazon・楽天ブックスの書籍ページでISBNが取得できない書籍率が5%未満

## 5. 機能要件

### 5.1 書籍ページの自動検出

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| FR-01 | Amazon.co.jp の書籍詳細ページ（`/dp/[ASIN]`）を自動検出する | Must |
| FR-02 | 楽天ブックスの書籍詳細ページ（`/rb/[数字]/`）を自動検出する | Must |
| FR-03 | 書籍ページ以外（検索結果・トップページなど）では何も表示しない | Must |

### 5.2 ISBN自動取得

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| FR-04 | AmazonページのURLに含まれるASIN（10桁数字）をISBN-13に変換する | Must |
| FR-05 | Amazon商品詳細セクションのDOMからISBN-13・ISBN-10を取得する（新旧両形式対応） | Must |
| FR-06 | 楽天ブックスのメタタグ・DOM・本文テキスト・URLパスからISBNを取得する | Must |
| FR-07 | ISBN取得に失敗した場合はウィジェットを表示しない（エラーを表示しない） | Must |

### 5.3 蔵書確認（ページ内ウィジェット）

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| FR-08 | 書籍ページ内の適切な位置（Amazon: 詳細情報直後、楽天: クーポンエリア直前）にウィジェットを挿入する | Must |
| FR-09 | ウィジェットはローディング状態→結果表示の順で表示を更新する | Must |
| FR-10 | 設定されたAPIキー・図書館を使ってカーリルAPIを呼び出す | Must |
| FR-11 | 図書館ごとに蔵書状況（貸出可・貸出中・館内のみ・予約中・準備中・休館中・蔵書なし）を表示する | Must |
| FR-12 | 各館の貸出状態をアイコン色とラベルで区別して表示する | Must |
| FR-13 | APIレスポンスに `reserveurl` が含まれる場合、予約ページへのリンクを表示する | Must |
| FR-14 | APIキーまたは図書館が未設定の場合、設定画面への誘導メッセージを表示する | Must |
| FR-15 | 同一タブ・同一ISBN・同一図書館設定のAPI結果をセッション中キャッシュして重複リクエストを防ぐ | Should |

### 5.4 ポップアップ表示

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| FR-16 | 拡張機能アイコンクリックで現在ページの蔵書状況をポップアップ表示する | Must |
| FR-17 | 非対応ページでは「対応サイトではありません」を表示する | Must |
| FR-18 | 図書館ごとに代表ステータス（貸出可 > 貸出中 > その他の優先順）をリスト表示する | Must |
| FR-19 | APIレスポンスに `reserveurl` が含まれる場合、各図書館の予約ページへのリンクをポップアップ内に表示する | Must |
| FR-20 | ポップアップから設定ページを開けるボタンを表示する | Must |

### 5.5 設定機能

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| FR-21 | カーリルAPIキーを入力・保存できる | Must |
| FR-22 | 都道府県・市区町村でカーリルAPIを使って図書館を検索できる | Must |
| FR-23 | 検索結果から最大5館を選択して登録・保存できる | Must |
| FR-24 | 設定は `chrome.storage.sync` に保存し、Chromeプロファイル間で同期される | Must |

## 6. 非機能要件

### 6.1 パフォーマンス

| 要件ID | 要件 |
|--------|------|
| NFR-01 | ネットワークエラー時はexponential backoffで最大3回リトライし、失敗時はエラー表示する |
| NFR-02 | カーリルAPIのポーリングは2秒間隔・最大10回で打ち切り、タイムアウトエラーとして表示する |
| NFR-03 | 複数図書館への蔵書確認はPromise.allSettledを使って並列実行する（1館の失敗が他に影響しない） |

### 6.2 セキュリティ

| 要件ID | 要件 |
|--------|------|
| NFR-04 | APIキーはコンテンツスクリプトに渡さず、Service Worker経由でのみAPIを呼び出す |
| NFR-05 | ページに挿入するテキストはすべてDOMのテキストノード経由で挿入する（XSS対策） |
| NFR-06 | ページに挿入するURLはhttp/httpsのみ許可し、それ以外は`#`に置換する |

### 6.3 互換性・動作環境

| 要件ID | 要件 |
|--------|------|
| NFR-07 | Chrome拡張機能 Manifest V3 に準拠する |
| NFR-08 | `chrome.storage.sync` の権限と `activeTab` 権限のみを使用する（最小権限の原則） |
| NFR-09 | 対象サイトのDOM変更に対応するため、Amazon・楽天ブックスともに複数のフォールバック挿入位置を持つ |

### 6.4 品質

| 要件ID | 要件 |
|--------|------|
| NFR-10 | Jest による自動テストを備え、主要モジュール（API・Service Worker・コンテンツスクリプト・ポップアップ）のカバレッジを確保する |
| NFR-11 | GitHub Actions で Node.js 20.x・22.x のマトリクステストを実施し、mainブランチへのPRをCIで保護する |

## 7. 制約・前提条件

| 項目 | 内容 |
|------|------|
| 外部API依存 | カーリル図書館API（https://api.calil.jp）が利用可能であること |
| APIキー | ユーザーが自身のカーリルAPIキーを取得・設定する必要がある |
| 対応ブラウザ | Google Chrome（Manifest V3対応バージョン） |
| 対応サイト | Amazon.co.jp・楽天ブックスのみ（他サイトは対象外） |
| 図書館データ | カーリルAPIが提供する図書館情報（全国7,400館以上）に依存する |
| API利用制限 | カーリルAPIの利用制限（1,000リクエスト/時）に配慮し、セッションキャッシュで重複リクエストを防ぐ |

---

## 8. 対象外（スコープ外）

- Amazon.co.jp・楽天ブックス以外の書籍サイトへの対応
- Firefox・Edge など Chrome 以外のブラウザへの対応
- ユーザー間での設定共有・ソーシャル機能
- 蔵書確認履歴の保存・管理機能
- カーリルAPI以外の図書館APIへの対応
- 拡張機能側でのAPIキーの発行・管理

## 10. 用語集

| 用語 | 説明 |
|------|------|
| カーリル | 全国の図書館蔵書を横断検索できるサービス（https://calil.jp）。本プロダクトはそのAPIを使用する |
| ISBN | 書籍の国際標準識別番号。13桁（ISBN-13）または旧形式の10桁（ISBN-10）がある |
| ASIN | AmazonのASIN（Amazon Standard Identification Number）。10桁数字のASINはISBN-10と同一 |
| systemid | カーリルAPIで図書館システムを識別するID（例: `Tokyo_Pref`） |
| libkey | カーリルAPIレスポンス内の館ごとの貸出状態マップ（例: `{"中央図書館": "貸出可"}`） |
| ポーリング | カーリルAPIの非同期検索において、`continue=1` の間は `session` パラメータを付けて再リクエストを繰り返す処理 |
| Service Worker | Chrome Manifest V3 のバックグラウンド処理。APIキーを保持しAPIへのリクエストを担う |
| コンテンツスクリプト | 書籍ページのDOMに注入されるスクリプト。ISBNの取得とウィジェットの表示を担う |
